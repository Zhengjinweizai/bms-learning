# 课程 ARCH-D：分布式 BMS——没有"主"的架构

> 对应节点 `ARCH-D`（[../domains/00-跨域层-架构与代际.md](../domains/00-跨域层-架构与代际.md)）｜ 前置：`ARCH-C`、`ARCH-MS`（建议先读）｜ 预计用时 30 min
> 数字规则：文中所有具体数字凡未挂标准/论文者均为**教学示意值**，用于建立量级直觉，不是实测数据。

## 1. 为什么需要：决策也要摊开

主从式解决了"采样线汇聚"，但**主板仍是单点**：它挂了，整包失智。分布式（Distributed BMS）把控制权也摊开：多个节点对等协同，无单一主控中心（domain 定义）。

适用动机：

1. **模块化可扩展**：簇数不定的系统（储能柜、特种车辆可换电池箱），"每节点自治 + 协议协同"比"换一块更大的主板"好扩展；
2. **无单点主控**的要求场景；
3. **地理分散**的大系统：单一主控的接线半径与可靠性都不够用。

## 2. 机制：对等协同的代价

### 2.1 每个节点都要"自给自足"

独立供电（隔离 DC/DC）、独立通信收发器、独立 MCU——每节点成本上升（domain 约束）。主从式从板可以共享主板的许多资源，分布式不能，这是分布式 BOM（物料清单）溢价的根源。

### 2.2 协同靠协议不靠中心

- CAN 本身就是多主总线（ISO 11898，S-11）：节点按 ID 仲裁发送消息——但**链路层多主 ≠ 应用层有权决策**；
- 决策一致性：谁有权下令断高压？需要协议层预定义（固定角色 + 冗余备份、超时接管等，示意机制）；
- 失效模式分散：单节点故障只影响局部，但故障管理逻辑复杂度上升（domain 约束）。

### 2.3 术语辨析（重要）

业界常把"从板物理分散"的主从式也叫"分布式"，必须分清口径：

| 口径 | 采样位置 | 决策位置 | 本项目口径 |
|---|---|---|---|
| 集中式 | 汇聚一点 | 一点 | `ARCH-C` |
| 主从式 | 模组就近 | 集中在主板 | `ARCH-MS` |
| 分布式 | 模组就近 | 分散到各节点 | 本课 |

## 3. 手算实例：8 模组储能簇的成本与失效账

设 8 个模组、每模组 16 串（教学示意值）。对比主从式（8 从板 + 1 主控）与分布式（8 个对等节点）：

| 项目 | 主从式 | 分布式 |
|---|---|---|
| 控制器数量 | 9（1 主 8 从） | 8 |
| 单节点必备件 | AFE + 均衡 + 通信接口 | AFE + 均衡 + MCU + 隔离电源 + 收发器 |
| 单节点 BOM 相对水平 | 1.0（基准） | 1.5~2.0（示意） |
| 全簇 BOM 相对水平 | 1.0（基准） | 1.2~1.4（示意） |
| 主控失效后果 | 整簇失智（需降级设计） | 不存在此单点 |
| 单节点失效影响 | 16 串失明 | 16 串失明 + 需协议补位 |
| 扩展到 16 模组 | 主控负载/总线需重核算 | 新节点入网即可 |

**结论**：分布式用约 20~40% 的 BOM 溢价（教学示意值）购买"无单点主控"与"可扩展性"——只在这两个属性真值钱的场景划算。

## 4. 工程实态

- 纯对等分布式在乘用车动力电池中极少量产（观点级）；行业语境说"分布式"多指主从式的从板物理分散。
- 储能系统的簇级管理（BMU/CMU 分层 + 环网冗余等，叫法待核对）更接近分布式思路（观点级）。
- 模块化商用车辆与换电包采用对等协同以支持"任意组合上架"（观点级）。

## 5. 常见误区

1. 把 CTP + 从板分散叫"分布式架构"——物理分散 ≠ 控制权分散，判据看决策位置。
2. "分布式天然更可靠"——软件协同、状态一致性、竞态决策是新的可靠性敌人；没有失效补位协议，反而更脆。
3. "分布式省成本"——省的是主控一份钱，涨的是 N 份"自给自足"（隔离电源/收发器/MCU），小系统净亏。

## 6. 自测

**Q1**：8 模组簇扩到 16 模组，主从式与分布式各要改什么？
**Q2**：CAN 链路层多主，为什么仍不能自动解决分布式的"谁有权断高压"问题？
**Q3**：分布式节点失效后的"协议补位"指什么？

<details><summary>答案</summary>

- Q1：主从式要核算主控负载与总线（或加级联网关），主板可能要换更大算力；分布式只需新节点按协议入网——扩展性差异正是本架构的存在理由（教学示意值场景）。
- Q2：CAN 的多主是链路层仲裁（谁都能发帧），不含"谁有权做安全决策"的应用层语义；后者须由协议与功能安全设计显式定义（角色、优先级、超时接管，S-07 框架）。
- Q3：指预定义的失效接管逻辑：某节点失联后，其安全职责（如该模组的过压判断）由邻居节点或系统级兜底机制接管，系统降容运行而非整簇停机（示意机制，具体策略项目自定义）。
</details>
