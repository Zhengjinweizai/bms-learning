# 课程 FLT-05：售后故障码归属判定

> 对应节点 `FLT-05`（[../domains/09-故障处理.md](../domains/09-故障处理.md)）｜ 前置：[FLT-02](FLT-02-DTC与冻结帧.md)、[SYS-02](SYS-02-系统边界与接口.md)、[SW-05](SW-05-标定与诊断.md) ｜ 预计用时 45 min
> 数字规则：文中案例数据均为**教学示意值**。

## 1. 为什么"谁的责任"是个工程问题

电动车质保体系里，电池包（电芯/包体）多由电池厂负责，整车集成与低压/热系统由主机厂负责——故障发生后"谁买单、谁整改"取决于责任在电池侧还是整车侧。节点约束点题：**责任判定依赖故障码语义清晰度——电池厂 vs 主机厂边界的高发争议区**。

三个前置条件（缺一个就变成扯皮）：

1. **边界事先写清**：哪类故障归属谁，在双方接口协议/质量协议里预定义（SYS-02 的边界定义落到商务条款）；
2. **语义事先对齐**：DTC/DID 语义是双方合同（SW-05），不允许"同一个码各解释各的"；
3. **证据事后可取**：快照完整、时间轴可信、存储防篡改（FLT-02 + SW-07）。

## 2. 机制展开：判定链路与归属矩阵

**（1）判定链路。**

```
车端 DTC + 快照（FLT-02）→ 售后/远程读取（FLT-06）
→ 语义解释（DTC 手册：谁定义谁维护）→ 归属矩阵查表 → 结论：电池侧 / 整车侧 / 第三方（桩）
→ 争议时：黑匣子数据回放仲裁（SW-07 事故数据）
```

**（2）典型归属矩阵（示意，真实矩阵在商务协议里）。**

| 故障现象 | 表面 DTC | 常见归属 | 依据 |
|---|---|---|---|
| 单体压差大/容量跳水的电芯本体问题 | 单体过欠压、SOH 异常 | 电池侧 | 电芯制造/电化学 |
| 冷却液泄漏导致的高温故障 | 单体过温 | **整车侧**（热系统） | 触发源在热回路 |
| 12 V 亏电导致 BMS 反复复位 | 通信丢失/自检失败 | 整车侧（低压系统） | 供电根因 |
| 充电桩不执行降流请求 | 单体过压 | 第三方（桩）/协议执行 | 充电报文时序 |
| 标定错误导致的误保护 | 各类误报 | 开发方（多为主机厂） | 标定数据 |

**关键认知：表面 DTC 的"位置"≠ 责任的"根因"。** 单体过温的码在电池上，根因可能在整车冷却没跟上——这正是"故障码语义清晰度"决定判定质量的原因（节点约束原文）。

**（3）证据三要素。** 时间戳可信（全链路对齐 UTC，SW-07）；快照覆盖触发前后；存储防篡改（安全启动 + 记录签名，[SAFE-05](SAFE-05-网络安全.md) 视角）。

## 3. 工程案例推演：快充跳枪后无法上高压（教学示意值）

**现场**：用户快充中"跳枪"（充电意外中止），仪表报动力电池故障，无法上电行驶。车辆拖回门店。

**取证**（按 FLT-02 纪律：读码 → 快照 → 扩展数据）：

- DTC-1：单体过压三级，快照：充电电流 180 A、最高单体 4.21 V（三元体系，示意）、BMS 已发出降流请求；
- DTC-2：BMS 与充电机通信超时，时间戳比 DTC-1 **晚 2.3 s**（示意）；
- 充电机侧日志（桩运营方提供）：充电机称"BMS 报文中止（BST）"。

**时间轴推演（归属判定的本质是时间轴取证）**：

- 若顺序为：过压发生 → BMS 请求降流 → 桩未执行/未收到 → 过压升级 → BMS 主动 BST 中止 → **责任链指向桩侧**（未按 GB/T 27930，S-05 响应降流请求），快照里的"降流请求 + 桩侧确认"报文是铁证；
- 若顺序为：通信先超时（车端 OBC/线束问题）→ 桩按协议保护性中止 → 电压测量在通信中断期间异常 → **责任链指向整车侧**——判断关键变成"通信超时的根因在车还是桩"，需两侧报文对账；
- 若 BMS 阈值标定错误（4.21 V 在该电芯规格内本不该报警，示意）→ **开发责任**——需要规格书对照（归属矩阵里最容易被遗忘的一类）。

三种结局对应三个买单方——**同一组故障码，证据的完整度决定结论**。

## 4. 工程实态

- 主机厂与电池厂通常设联合售后分析流程：远程初判（FLT-06）→ 拆解/数据回放 → 双方签认；
- 责任矩阵条款化：接口协议/质量协议中预列"故障类别 → 归属 → 赔付/整改"（SYS-02 的商务落地）；
- OTA 类修复（标定）占比上升（趋势观点）：越来越多"故障"最终归类为软件问题，跨双方责任域；
- 争议高发位：热系统交互故障（THM-03）、充电交互故障（CHG 域）、低压供电——都是"码在电池、根因在整车"的典型区。

## 5. 常见误区

1. 故障码在哪，责任就在哪——DTC 是症状不是根因（归属矩阵第二行）；
2. 只看当前 DTC 不看历史时序——先因后果颠倒（案例时间轴）；
3. 语义没对齐就签协议——争议时双方各执一份"自己版本"的 DTC 手册；
4. 快照环形缓冲覆盖了关键事件——高频低价值事件把关键快照冲掉（SW-07 的策略问题）。

## 6. 自测

**Q1**：为什么说归属判定"本质是时间轴取证问题"？
**Q2**：单体过温故障码为什么可能归属整车侧？
**Q3**：为避免案例第三种结局（标定错误争议），开发阶段应该做什么？

<details><summary>答案</summary>

- Q1：同一组故障码在不同触发顺序下对应完全不同的责任链（案例的三种结局）；只有可信时间戳 + 完整快照能把"顺序"钉死，否则判定退化为立场之争。
- Q2：触发源可能在外：冷却液泄漏/流量不足/水泵失效都会让电芯被动升温——码由 BMS 报出（它只看得见自己的温度），根因在整车热系统；判定要靠冷却液侧证据（水温、流量、泵状态快照）反推。
- Q3：①阈值/倍率地图等关键标定在双方联合评审下冻结并留档（版本可追溯）；②规格书边界与 BMS 阈值的裕度分析成文；③DTC 手册里给每码标注"可能根因域"——把归属预判写进语义合同（SW-05）。
</details>
