# 课程 DEV-01：V 模型开发流程——需求到测试的对应关系

> 对应节点 `DEV-01`（[../domains/10-开发验证.md](../domains/10-开发验证.md)）｜ 前置：无 ｜ 预计用时 40 min
> 数字规则：文中所有具体数字凡未挂标准/论文者均为**教学示意值**，用于建立量级直觉，不是实测数据。

## 1. 为什么需要 V 模型

BMS 是安全相关系统：误切断高压有车辆失控风险，漏保护有热失控风险。ISO 26262:2018（S-07）把开发组织成一条**双向可追溯**的链：左臂逐层分解需求，右臂逐层集成验证，每一层都能回答"这个测试验证哪条需求、这条需求被哪些测试覆盖"。

没有这条链的团队，会反复踩三个坑：

1. 改了一个保护阈值，忘了同步改测试用例与标定文档，问题在路试才炸出来；
2. 需求写了"及时切断"，没人说清"及时"是 100 ms 还是 5 s，测试无从判定；
3. 法规试验（`DEV-04`）前才发现某个保护功能从未被集成测试过。

## 2. 机制：V 的左右两臂（框架依据 S-07）

```
车辆需求 ──→ 系统需求/架构 ──→ 软/硬件设计 ──→ 单元实现
   │               │                │              │
验收测试 ←── 系统集成测试 ←── 集成测试 ←──── 单元测试
```

- **左臂**：需求分解 + 架构设计。每层输出"下一层的输入"，同时输出"对本层的验证准则"。
- **右臂**：集成与验证，顺序与左臂相反（单元 → 集成 → 系统 → 验收）。
- **双向追溯**（bidirectional traceability）：需求 ↔ 设计 ↔ 代码 ↔ 测试用例；任何变更做**影响分析**（impact analysis）。

### 手算实例 1：安全需求的时间预算分解

需求 REQ-SYS-012（编号示意）："电芯电压 > 4.25 V（教学示意值）持续时，BMS 应在 500 ms（教学示意值）内请求停止充电。"

把 500 ms 分配到架构（全部教学示意值）：

| 环节 | 预算 |
|---|---|
| AFE 采样周期 | 100 ms |
| 滤波/防抖（连续 3 次超限） | 200 ms |
| 判断与通信 | 10 ms |
| 继电器动作 | 50 ms |
| 余量 | 140 ms |
| **合计** | **500 ms** |

每个子预算变成下层需求与下层测试的判据——这就是"需求可测化"。

### 手算实例 2：V 模型左右对应表

| 左臂产出 | 右臂对应验证 | 暴露的典型错误 |
|---|---|---|
| 系统需求（含安全需求） | 整车/台架验收（含法规试验，`DEV-04`） | 需求错漏、场景缺失 |
| 系统架构（采样/控制/执行链路） | 系统集成测试（`DEV-03` HIL） | 接口/时序不匹配 |
| 软件架构与详细设计 | 集成测试 | 模块间资源冲突 |
| 单元（函数/任务） | 单元测试（覆盖率见 `DEV-02`） | 逻辑边界错误 |

## 3. 工程实态

- 流程框架普遍参考 **ISO 26262**（S-07）与 **Automotive SPICE**（ASPICE，汽车行业过程评估模型）；国内团标 S-19 提供设计规范层面的落地要求。
- 追溯矩阵用需求管理工具维护（DOORS、Polarion 一类，行业通用工具，仅点名）；追溯矩阵是审核（audit）的第一检查物。
- 变更不是禁区：需求变更 → 影响分析 → 追溯链上所有受影响项（设计、代码、测试、标定）重开；量产阶段的变更评审更重。

## 4. 常见误区

1. **"V 模型 = 瀑布模型"**——V 强调对应与追溯，不要求左臂全部冻结才开右臂；迭代开发同样必须维护追溯。
2. **"测试是右臂的事"**——右臂测什么由左臂的验证准则决定；需求不可测，右臂必漏测。
3. 追溯矩阵只为应付审核——它的真价值是变更时自动圈出受影响范围；事后补的追溯链在变更时会大面积失效。
4. 把"演示功能可用"当"验证通过"——没有预定义判据的演示不属于验证（对 S-07 验证定义的转述，原文表述待核对）。

## 5. 自测

**Q1**：手算实例 1 中，防抖从"连续 3 次"改成"连续 5 次"（采样周期 100 ms 不变），时间预算要怎么调？
**Q2**：为什么"需求可测化"是 V 模型左臂的硬要求？
**Q3**：软件工程师把过压阈值从 4.25 V 改成 4.22 V，按 V 流程应触发哪些动作？

<details><summary>答案</summary>

- Q1：防抖 5 次占 400 ms，只剩 90 ms 给采样/判断/执行，预算表必须重排（或提高采样频率），否则 500 ms 总预算失守——防抖次数是左右臂联动的典型参数。
- Q2：右臂每个测试的判据来自左臂需求；不可测的需求产不出判据，该需求的验证悬空，追溯链在此断裂。
- Q3：发起变更单 → 影响分析（涉及该阈值的设计文档、代码、单元/集成/系统测试用例、标定条目、FMEA 等安全分析）→ 全链更新并重跑受影响测试 → 评审关闭。只改代码不改用例就是追溯链断裂。
</details>
