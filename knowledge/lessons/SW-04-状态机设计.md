## 1. 为什么模式管理必须用状态机

BMS 的"行为"由有限几个模式组成：下电、待机、预充、高压上电、运行、充电、故障。模式间的切换是**带条件的跃迁**——预充没完成就闭合主继电器是事故，故障态不收敛是甩锅。节点约束点题：**时序需与整车协调（预充条件、继电器时序）；迁移条件需防抖**。if-else 堆出来的"模式"既测不全也证不了，状态机（FSM, Finite State Machine）把行为变成**可枚举、可全覆盖测试**的表。

## 2. 机制展开：四要素 + 两条纪律

**（1）四要素**：状态集合、事件/条件集合、迁移（条件 → 动作 → 次态）、入口/出口动作。

**（2）纪律一：防抖（去毛刺）**——迁移条件必须"连续 N 次成立"才生效（n-of-m 计数），防止单拍电压毛刺把系统从预充踢进故障。防抖参数是标定项（[SW-05](SW-05-标定与诊断.md)）。

**（3）纪律二：防御性默认**——任何"未定义事件"统一进**安全态**（断开继电器），绝不"留在原态继续看"。状态机的完整迁移表 = 明确迁移 + 默认迁移，缺默认分支的表不完整。

**（4）与整车协调**：预充由 VCU 请求触发（接口来自 [SYS-02](SYS-02-系统边界与接口.md)），继电器时序由 BMS 硬件能力决定（[HW-05](HW-05-执行器驱动.md) 的 150 ms 预充 + 判据），两边在状态机的迁移条件里汇合。

**（5）分层状态机（HSM, Hierarchical State Machine）**：Run 与 Charge 共享"高压已上电"父态；Fault 是顶层旁路态，任何子态的故障事件直接跃迁——分层避免状态爆炸，旁路保证故障路径唯一。

## 3. 工程案例：上下电状态机迁移表

### 迁移表（条件均为示意，防抖以连续计数为准）

| 当前态 | 事件/条件（防抖） | 次态 | 动作 |
|---|---|---|---|
| PowerDown | 整车 KL ON 且无等级 3 故障 | Standby | 自检、粘连检测通过后待命 |
| Standby | VCU 请求高压 + 粘连检测通过 | PreCharge | 闭合主负、闭合预充 |
| PreCharge | V_link ≥ 0.95 × V_pack **连续 3 周期**（10 ms 周期） | HV_On | 断预充、闭合主正 |
| PreCharge | 预充超时 500 ms（示意） | Fault | 断预充、记 DTC |
| HV_On | 充电插枪确认 | Charge | 切充电功率策略 |
| Charge | 充电完成/拔枪 | HV_On → Standby（经下电时序） | 断高压时序 |
| 任意态 | ASIL 相关故障（[SAFE-04](SAFE-04-安全机制与FTTI.md)） | Fault | 按故障等级执行 |
| Fault | 故障清除 + 下电时序完成 | PowerDown | 存 DTC 与快照 |

### 伪代码片段（核心迁移骨架）

```c
switch (state) {
  case STANDBY:
    if (vcu_hv_req && weld_check_ok_n_of_m(3)) {
        close_relay(MAIN_NEG); close_relay(PRECHARGE);
        precharge_timer = 0;  state = PRECHARGE;
    } else if (undefined_condition) state = FAULT;   /* 默认迁移 */
    break;
  case PRECHARGE:
    if (v_link >= 0.95 * v_pack) debounce_cnt++; else debounce_cnt = 0;
    if (debounce_cnt >= 3) {                            /* 防抖达标 */
        open_relay(PRECHARGE); close_relay(MAIN_POS);   /* 先断预充再合主正 */
        state = HV_ON;
    } else if (++precharge_timer > 50) state = FAULT;   /* 500 ms 超时 */
    break;
  default: state = FAULT; break;                        /* 防御性默认 */
}
```

时间自洽检查：预充充电至 95% 需 150 ms（[HW-05](HW-05-执行器驱动.md) 实例）+ 3 周期防抖 30 ms = 180 ms < 超时 500 ms ✓——**防抖时长必须加进超时预算**，这是迁移表与硬件时序对账的固定动作。

## 4. 工程实态

- 模式管理独立成 SWC（[SW-01](SW-01-软件架构.md)），与 NM 网络状态（睡眠/唤醒，[HW-06](HW-06-通信收发器.md)）联动：总线睡眠前状态机必须已回 PowerDown；
- 测试要求：**迁移全覆盖**（每条迁移至少一次）+ 非法事件轰击测试（ISO 26262-6 对结构覆盖的要求方向，S-07）；
- 预充条件与超时是标定矩阵成员，随继电器/电容参数平台化调整（HW-05 的 RC 决定 3τ）；
- 状态快照入 NVM：故障/下电时记录当前态，支撑售后与云端分析（[SW-07](SW-07-数据记录与上云.md)）。

## 5. 常见误区

1. 迁移条件不防抖——电压毛刺一拍，预充中断、整车抖一下；
2. 状态扁平不分层——Run/Charge/Regen 两两组合后状态数爆炸，覆盖率测试做不动；
3. 两个状态机抢同一执行器（隐藏并发）——继电器必须有唯一 owner，其他模块只能提请求；
4. 超时预算不含防抖时长——3×防抖 + 硬件 3τ 超过超时值，"永远到不了"的合法迁移变成常态故障。

## 6. 自测

**Q1**：防抖 5 周期（10 ms 周期）+ 预充 3τ = 150 ms，超时最少应设多少（留 30% 余量）？
**Q2**：为什么 Fault 态要设计成"顶层旁路"而不是普通兄弟态？
**Q3**：迁移条件"V_link ≥ 0.95 × V_pack"直接用单次采样判定有什么风险？

<details><summary>答案</summary>

- Q1：150 + 50 = 200 ms → ×1.3 ≈ **260 ms**（取 300 ms 档更稳，示意）。预算 = 硬件时间 + 防抖时间 + 余量。
- Q2：故障可能在任何子态发生（包括迁移途中）；旁路态保证故障路径唯一、动作唯一（断高压），不需要在每个子态重复写故障处理。
- Q3：单拍判定对毛刺零防御——AFE 采样噪声、继电器弹跳都可能造成一拍假达标，先合主正后断预充的时序被毛刺触发就是事故。
</details>
