# 课程 SAFE-03：ASIL 分解——用冗余换成本

> 对应节点 `SAFE-03`（[../domains/02-安全设计.md](../domains/02-安全设计.md)）｜ 前置：[SAFE-02](SAFE-02-HARA.md) ｜ 预计用时 45 min
> 数字规则：分解规则源自 ISO 26262-9:2018（S-07）；案例数字均为**教学示意值**。

## 1. 为什么需要分解

HARA 出了 ASIL D（`SAFE-02` 的过充场景 H-01），按 D 级开发单通道系统：全链路 D 级硬件、MC/DC 软件覆盖、全套分析——成本陡峭。工程出路：**如果架构上存在足够的冗余（两条独立通道都能达成安全状态），可把安全需求分解到两条通道，各自按较低 ASIL 开发。** 节点约束：**分解需满足独立性/免干扰准则；冗余通道需各自诊断覆盖。**

## 2. 机制展开：分解规则与两个前提

**（1）合法的分解组合**（ISO 26262-9:2018 Clause 5；记法 X(n) = "按 ASIL X 开发、验证严格度保留 n 级"的需求）：

| 原始 ASIL | 可分解为 |
|---|---|
| D | C(D) + A(D)，或 B(D) + B(D)，或 D(D) + QM(D) |
| C | B(C) + A(C)，或 C(C) + QM(C) |
| B | A(B) + A(B)，或 B(B) + QM(B) |

**ASIL A 不可再分解，QM 亦不可分解**（2026-11-13 核实，多个公开来源一致：Infineon 知识库等；本课此前误列 "A → A(A)+QM(A)" 一行，已删除）。

记法解读：**括号里的 D/C/B/A 是"残余 ASIL"**——每条分解后的需求保留原始 ASIL 的验证严格度属性，用于确认活动与后续再分解；QM(n) 不是"不管"，它仍承载安全相关需求，只是按质量流程开发。

**（2）两个前提（违反即分解无效）**
- **独立性（Independence）**：两通道间不存在共同原因失效（common cause）与级联失效（cascading failure）——必须用 DFA（Dependent Failure Analysis，相关失效分析）论证；
- **免干扰（Freedom from Interference）**：低 ASIL 通道的失效不得干扰高 ASIL 通道的功能（内存分区、时间监视、通信 E2E）。

**（3）不可省略的收尾**：每条通道**各自保留诊断覆盖**（分解不是把监控拆掉）；系统层仍要回归验证整体安全目标达成。

## 3. 工程案例推演：过充安全目标 ASIL D 的两条分解路线

沿用 SG-01"防止任一电芯超过充电电压上限"（ASIL D，示意）。

**路线甲：C(D) + A(D)**

| 通道 | 内容 | ASIL |
|---|---|---|
| 通道 1（主控） | 软件电压监控 + 判断 + 驱动断接触器 | C(D) |
| 通道 2（监控） | 独立监测电路（硬件比较/独立监控芯片）检测过压直接触发 | A(D) |

**路线乙：B(D) + B(D)**：主控与监控各自做完整的"检测+判定"，互为冗余，两路独立驱动或采用双接触器。

**DFA 清单（教学示意）**——逐项论证独立性：

| 检查项 | 路线甲的答案 |
|---|---|
| 供电 | 监控通道独立供电轨（否则单电源故障击穿两通道） |
| 信号路径 | 电压采集路径独立于主控 AFE（独立采样点/走线） |
| 时钟/晶振 | 各自独立时钟源 |
| 软件 | 监控通道为硬件实现或独立软件分区（免干扰） |
| **执行器** | **共同执行器（同一接触器）是单点**——接触器"按指令断开"的功能必须自身满足剩余 ASIL，或改双接触器方案 |

最后一条是分解设计的高频翻车点：**两条"独立"通道汇入同一个接触器，接触器焊死（粘连）就是共同原因失效**——`HV-04` 粘连检测因此成为分解方案的必备配套。

**定量目标说明**（谨慎表述）：分解不放松安全目标层面的整体随机硬件失效要求；工程做法是各通道按分解后 ASIL 的度量开发，再在系统层验证整体指标达标。Part 5 与 Part 9 的衔接规则引用前以标准原文为准（见待核对项）。

## 4. 工程实态

- 量产形态：主控 MCU（软件全功能）+ 独立监控芯片/硬件比较器（兜底）是最常见的"过充 ASIL D 落法"；
- 双 MCU 锁步（lockstep）处理的是**单芯片内部**失效，与跨芯片分解是两回事（`HW-02`）——不要混淆；
- 免干扰在软件侧的落点：内存分区（MPU）、看门狗/程序流监视、E2E 保护（`SW-01/02`）；
- 分解是架构决策：没有冗余架构就没有分解——先有架构（如 `ARCH-MS` 从控板的独立性），再谈分解，顺序不能反。

## 5. 常见误区

1. 把分解当降级（"D 变成 B 了，随便做做"）——每条通道仍需各自诊断覆盖与残余 ASIL 严格度；
2. 忽略共同执行器/共同电源——DFA 漏一项，分解论证整体失效；
3. 把 QM(D) 当成纯 QM——QM(D) 仍承载安全需求，需要实现并验证其存在；
4. 对非冗余架构硬套分解——串联结构（一个通道失效即失去保护）不满足分解前提。

## 6. 自测

**Q1**：ASIL B 可以分解为哪两种组合？
**Q2**：两条独立通道都通过同一个接触器执行断开，有什么问题？怎么解？
**Q3**：记法 B(D) 中括号里的 D 是什么含义？

<details><summary>答案</summary>

- Q1：A(B) + A(B)，或 B(B) + QM(B)。
- Q2：执行器成为共同原因单点，DFA 无法闭合。解法：执行器按剩余 ASIL 开发/验证，或改双接触器冗余执行；并配套粘连检测（HV-04）覆盖焊死失效。
- Q3：残余 ASIL——该需求保留原始 ASIL D 的验证严格度属性（用于确认活动与后续操作），开发严格度按 B。
</details>
