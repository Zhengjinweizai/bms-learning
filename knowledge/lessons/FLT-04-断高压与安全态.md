# 课程 FLT-04：断高压与安全状态设计

> 对应节点 `FLT-04`（[../domains/09-故障处理.md](../domains/09-故障处理.md)）｜ 前置：[HV-05](HV-05-上下电时序.md)、[HV-04](HV-04-粘连检测.md)、[FLT-01](FLT-01-故障分级.md) ｜ 预计用时 60 min
> 数字规则：文中所有时间/阈值数字均为**教学示意值**；绝缘阈值等以标准原文为准（待核对项见文末）。

## 1. 为什么"断开"本身也是危险动作

断高压（contactor opening，接触器断开）是 BMS 手里最重的处理，但断开这个动作自带三种次生风险：

1. **带载拉弧**：大电流下触点分离产生电弧，烧蚀甚至熔焊触点——熔焊粘连后**下次就再也断不开了**（[HV-04](HV-04-粘连检测.md) 检测的就是这个后遗症）；
2. **行驶失电**：高速中断动力本身就是整车级危害（HARA 视角，[SAFE-02](SAFE-02-HARA.md)）——断高压可能把电池风险换成交通事故风险；
3. **低压连锁**：断高压即断 DC/DC 输入，12 V 网失去充电来源——转向助力/灯光/解锁依赖 12 V 电池续命。

所以本节点真正的问题是：**什么条件下断、以什么顺序断、断成什么样算"安全"**——安全状态（safe state）的设计。节点约束点题：需区分正常下电/故障下电；行驶中断高压需评估次生风险。

## 2. 机制展开

**（1）两条断开路径。**

- **正常下电**：VCU 请求 → BMS 先降载至 0（等电流趋零）→ 断主正/主负 → 时序见 [HV-05](HV-05-上下电时序.md)；
- **故障下电**：分级触发。时间充裕的（三级降级先行）尽量"先降载再断"；不可等的（碰撞、严重绝缘失效、热失控确认）立即断——**接受带载拉弧的代价**，因为继续带电的风险更大。

**（2）断开执行与确认。** 主正、主负分路独立驱动（[HW-05](HW-05-执行器驱动.md)）；断开后用电压/粘连检测（HV-04/HV-03）确认"真断开"；断开状态入快照（[FLT-02](FLT-02-DTC与冻结帧.md)）。

**（3）安全状态（safe state）的要素。** ISO 26262（S-07）框架下，safe state 是安全目标可达且可维持的状态。对高压电池通常意味着：回路断开且验证、无失控热风险、低压可维持、状态可被乘员与售后理解——断高压只是进入 safe state 的**手段**，不是 safe state 本身。

**（4）决策树骨架（示意）。**

```
触发源？──碰撞信号 ──────────────→ 立即断（FTTI 毫秒~百毫秒级）
        ├─绝缘 < 阈值 ─┬─停车/充电中 → 先请求降流至 0 再断
        │              └─行驶中 → 限功率提示 + 按策略断（策略因厂而异）
        ├─热失控确认（THM-05 三级）→ 断 + 整车联动（报警/解锁/排烟）
        └─继电器控制失灵/过流 → 熔断器兜底（硬件路径，不依赖软件）
```

## 3. 工程案例：三个场景的决策推演（教学示意值）

**场景 A：停车充电中，绝缘电阻降到 80 Ω/V（示意；标准要求量级 100 Ω/V DC，待核对）。**

非行驶 → 无失电风险 → 直接走断开流程；但断前先用 GB/T 27930（S-05）停机流程请求充电机降流至 0（中止充电报文时序）——**避免带载拉弧**。断开后停充状态锁存，维修前禁止再上高压。

**场景 B：120 km/h 行驶中，热失控二级前兆（未确认）。**

危险尚未确认、断电代价巨大 → 限功率 + 高级报警，请求靠边；升级为三级确认（THM-05 多信号交叉）→ 断 + 联动。**"行驶中要不要为未确认的威胁断电"没有普适答案，是安全论证（SAFE-02/04）逐项目决定的权衡**——这就是节点约束"行驶中断高压需评估次生风险"的含义。

**场景 C：碰撞信号（气囊控制器广播）到达。**

无条件立即断——事故后电池是二次伤害源（短路/漏电/起火）。断开执行链路时间预算：信号确认 + 逻辑判断（毫秒级）+ 接触器机械动作（10~30 ms，示意）→ **百毫秒内完成**（示意），与碰撞安全 FTTI 匹配。

## 4. 工程实态

- 碰撞信号断高压是行业通用实践（工程共识）；断开指令有多重来源（BMS 逻辑、碰撞信号、人工维修开关 MSD、熔断器物理熔断）——**软件失效有硬件兜底**；
- 断开后 12 V 电池接管低压（灯光/解锁/报警），DC/DC 停止工作；
- 断高压事件必须落快照 + 云端事件包（[FLT-06](FLT-06-远程诊断.md)）——这是售后归属判定（[FLT-05](FLT-05-售后归属判定.md)）的核心证据；
- 粘连后的处理：检测告警 + 维修更换接触器，无法软件恢复（HV-04）。

## 5. 常见误区

1. 把断高压当万能解——行驶失电是新的危害源，断开时机要用 HARA 论证而不是"越早越好"；
2. 故障下电不先降载——继电器带载拉弧、粘连，把一次故障变成永久性硬件损坏；
3. 断开后不记录、不上传——售后面对"黑箱"，责任判定无从谈起；
4. 正常下电与故障下电共用慢时序——紧急路径必须最短（碰撞场景百毫秒级，示意）。

## 6. 自测

**Q1**：为什么充电中的绝缘故障要"先请求降流再断"，而碰撞信号"立即断"？
**Q2**：行驶中收到未确认的热失控前兆，断还是不断？设计依据是什么？
**Q3**：断高压之后，车上还有哪些功能必须继续工作？靠什么供电？

<details><summary>答案</summary>

- Q1：充电中时间不紧迫（无行驶风险），降流至 0 后断开可避免带载拉弧，保护继电器不粘连；碰撞时每毫秒都在增加二次伤害风险，且电流已不可控——立即断的收益远大于触点损耗，FTTI 也只允许立即断。
- Q2（示意答案）：不立即断——限功率 + 报警 + 请求靠边，同时加密监测；升级到确认（多信号交叉）再断。依据：断高压的次生风险（高速失电）与电池风险的期望损失比较，由 HARA/安全论证给出该项目阈值（SAFE-02/04），并保留乘员/人工断电入口。
- Q3：危险报警灯、门锁解锁、报警发声、（事故后）紧急呼叫——全部挂 12 V 低压网，由 12 V 电池供电（DC/DC 已随断高压停止）；所以低压电池的容量与状态也是安全链路的一部分。
</details>
