# 课程 DEV-07：AI 模型的验证体系

> 对应节点 `DEV-07`（[../domains/10-开发验证.md](../domains/10-开发验证.md)）｜ 前置：`DEV-02`、`ALG-05` ｜ 预计用时 50 min
> 定位提醒：本节点在图谱中标记为 `frontier` 且 **[需补约束]**——AI 验证的接受准则在行业内**尚未收敛**，本课给的是"已形成共识的框架 + 诚实标注未决问题"。安全侧对应物是 `SAFE-06`（AI 安全论证）。

## 1. 为什么 AI 组件需要另一套验证

ML（machine learning，机器学习）正进入 BMS 的 SOH 估计、析锂检测、充电优化等功能（综述见 S-28、S-29；SAE 2026 年论文 S-21 为候选证据，全文待核对 → P-11）。传统 V 模型的验证手段在 ML 面前有三处失效：

- **覆盖率失义**：代码覆盖率 100% 不等于输入空间被覆盖——神经网络的输入空间是连续高维的，无法穷举；
- **通过准则缺失**：物理模型的误差界限可按机理推导，ML 的接受准则目前**没有行业收敛的标准**（这就是域 [需补约束] 的含义）；
- **失效模式不同**：物理模型错得"讲得出理由"，ML 会**沉默地错**——分布外输入照样给出自信的输出。

验证重心因此从"代码对不对"转向"数据对不对、域边界在哪、错了怎么办"。

## 2. 机制：五层验证框架（框架层为工程共识，条款级标准未收敛）

1. **数据集验证**：训练/验证/测试切分；切分方式必须匹配泛化目标（见手算实例）；数据来源与标注可追溯。
2. **指标与接受准则**：精度指标（MAE/RMSE）+ 不确定性量化（UQ，uncertainty quantification，让模型输出"我有多确定"）+ 失效代价加权；准则由功能安全团队按应用场景商定并留档。
3. **运行域定义（ODD，Operational Design Domain）**：明确模型在什么温度/SOC/倍率域内可信；域外输入要么拒绝、要么降级。
4. **鲁棒性与分布外测试（OOD，Out-of-Distribution）**：噪声注入、传感器漂移注入、域外工况探测。
5. **兜底与降级（fallback）**：ML 输出异常时回退到物理模型/保守策略——让"ML 会错"变成可安全承受的事件。

标准语言：ISO 26262（S-07）覆盖代码与系统，ISO 21448:2022（SOTIF，预期功能安全，标准直引）提供"性能局限/已知未知"的分析语言，UL 4600（标准直引）提供安全论证（safety case）框架——三者如何组合用于 BMS 的 ML 组件，**尚无收敛答案**。

### 手算实例：一个 ML-SOH 估计器的验证（核心案例，数字均为教学示意值）

- 任务：电芯 SOH 估计；数据：公开数据集 CalCE（S-32），12 颗电芯训练、4 颗测试；
- 验收准则（项目自定，示意）：MAE ≤ 2%，95% 分位误差 ≤ 4%；
- 实测：按"电芯"切分测试集，MAE = 1.5% ✓；
- **切分陷阱对照**：改按"循环序号"切分（同一颗电芯相邻循环分进训练/测试集）→ MAE 虚降到 0.3%——相邻循环几乎一样，这是**数据泄漏**（data leakage），不是泛化能力；
- OOD 测试：训练集温度 10~40 ℃，喂入 -20 ℃ 数据 → MAE 恶化到 8% → 结论：运行域限定 [10, 45] ℃（示意），域外回退到安时积分 + 容量核查（`ALG-01`/`ALG-05` 的物理方法）。

## 3. 工程实态

- 量产普遍走**混合架构**：ML 出精细值，物理模型守边界，超界即回退；纯 ML 直接控执行器的 BMS 功能尚未成为主流（观点级）。
- 发布前影子模式评估（`DEV-06`）+ 发布后持续监控（误差漂移告警）——"验证不止于发布"。
- 数据闭环（`DEV-06`）承担 ML 的"再验证"：车型/批次/季节变化触发重训与重测。

## 4. 常见误区

1. **把测试集精度当安全证据**——精度是统计性能；安全论证要回答"最坏情况会怎样、错了伤到谁"。
2. **数据泄漏**（见手算实例）——SOH 任务还常见"同一颗电池全寿命数据被拆到两边"，实车泛化能力被严重高估。
3. 忽略**分布漂移**（distribution shift）——车型/批次/季节变化后模型悄悄变差，没有监控就永远发现不了。
4. 用"可解释性差"当借口跳过失效分析——至少要能回答"输入什么特征时模型不可信"。

## 5. 自测

**Q1**：手算实例中两种切分方式，哪种对应"换一批新电芯也能用"的泛化目标？为什么？
**Q2**：为什么 OOD 测试要单独做，不能指望测试集自带代表性？
**Q3**：ML-SOH 上线后，云端应监控哪些量来发现"静默退化"？

<details><summary>答案</summary>

- Q1：按"电芯"切分——模拟"模型没见过这颗电芯"的真实部署；按循环切分时测试与训练来自同一颗电芯、高度相似，考的是"记忆"不是"泛化"。
- Q2：测试集只评估"与训练同分布"的性能；OOD 测试评估分布边界之外的失败方式（告警与回退是否有效），是运行域定义与兜底设计的依据，测试集给不出。
- Q3（示例）：①在线预测值与满充容量核查值（真实锚点）的偏差趋势；②输入特征的分布漂移（季节温度、新电池批次）；③模型不确定性输出的漂移；④触发回退/拒绝的频次变化。
</details>
