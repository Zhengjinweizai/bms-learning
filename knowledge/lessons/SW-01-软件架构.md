# 课程 SW-01：软件架构——AUTOSAR CP 与裸机两条路

## 1. 为什么架构是"集成边界的合同"

BMS 软件是三件事的合体：采集与算法、整车通信、安全机制。架构（Architecture）回答的不是"怎么写代码"，而是**"谁和谁通过什么接口说话、换一家供应商要换多少东西"**。节点约束点题：**AUTOSAR CP 利于主机厂集成但资源占用高；裸机平台需自证安全机制**。这也是"电池厂 vs 主机厂集成边界"争论（compare/matrix.md）的技术底座——架构选型就是商业边界的落笔。

## 2. 机制展开：两条路线逐层看

**（1）AUTOSAR CP（Classic Platform）路线——分层标准化**

| 层 | 内容 | 作用 |
|---|---|---|
| MCAL（Microcontroller Abstraction Layer，微控制器抽象层） | 芯片外设驱动（ADC/SPI/_CAN/定时器） | 换 MCU 只换这层 |
| BSW（Basic Software，基础软件） | OS、CanIf/CanTP、PduR、COM、NM、Dcm/Dem（诊断）、NvM（存储）、Csm（加密） | 标准化中间件，配置生成 |
| RTE（Runtime Environment，运行时环境） | SWC 之间/与 BSW 的接口胶水 | 应用与平台解耦 |
| SWC（Software Component，软件组件） | BMS 应用：SOC 算法、状态机、保护逻辑 | 电池厂核心资产 |

价值：主机厂拿到标准接口的 BMS，可换 Tier1 而不动整车侧；代价：BSW 资源占用大、配置工程量大、许可费用。

**（2）裸机/自研路线——前后台或轻量 RTOS**
- 前后台：主循环轮询 + 中断采集，简单直接、资源极省；
- 轻量 RTOS + 自研中间件：调度有保障，但通信栈、诊断栈、存储管理全要自己做；
- **安全机制要自证**：ISO 26262（S-07）不关心你用不用 AUTOSAR，关心的是"程序流监控、E2E 保护、存储保护、看门狗"这些机制有没有、证据全不全——自研路线的安全论证成本常被低估。

**（3）混合形态（量产常见）**：AUTOSAR BSW 做通信/诊断 + 自研 SWC 装算法——两头占，但集成与配置能力要齐备。

## 3. 手算实例：RAM/Flash 资源预算

设 ASIL 级 BMS 主控，MCU RAM 128 KB、Flash 1 MB（示意档位），CP 方案预算（教学示意值）：

| 模块 | RAM |
|---|---|
| OS + 栈（多任务各自栈） | 8 KB |
| BSW（COM/NM/诊断/存储管理） | 30 KB |
| RTE | 3 KB |
| 应用 SWC（算法缓冲、状态） | 45 KB |
| **合计** | **86 KB → 占用 67%** |

- 67% 已逼近工程警戒线（余量需留给故障模式下的记录与降级，参考 [HW-02](HW-02-主控MCU.md) 的余量逻辑）；
- Flash 侧：MCAL + BSW 典型占数百 KB（示意 450 KB），加应用后 1 MB 档位紧张——**这就是"AUTOSAR CP 资源占用高"的量化含义**：CP 路线基本锁定 512 KB~1 MB Flash、128 KB+ RAM 的 MCU 档位，裸机路线 64 KB Flash / 8 KB RAM 也能做从控板（示意量级）；
- 选型规则：预算表按"稳态 + 故障降级态"各做一份，取大者。

## 4. 工程实态

- 量产两条路线长期并存（工程共识）：从控板/低端包用裸机或轻量自研，主控/平台化项目用 CP；
- OEM 的接口规范（通信矩阵、诊断需求）决定下限：要求 UDS 全服务 + AUTOSAR 接口时，自研路线的"自证"成本可能反超 CP；
- T/CAAMTB 团标《电动汽车用电池管理系统设计规范》（S-19，编号待核对 P-01）代表行业对架构分层的规范化尝试；
- 架构评审要过 ISO 26262-6 的软件架构原则（分层、低耦合、可验证性，S-07）。

## 5. 常见误区

1. "用了 AUTOSAR 就安全了"——CP 提供的是**机制的标准位置**（Dem/Dcm/NvM 等），机制本身要配置和开发，证据要自己攒；
2. "裸机便宜"——只算资源不算安全论证与长期维护，自研诊断栈的 bug 修复成本远超许可费；
3. 把算法塞进 BSW 层——RTE 接口被私有化，平台复用性归零；
4. RTE 全家桶配置——只用得上几个端口的 SWC 却生成整套 RTE，RAM 白烧。

## 6. 自测

**Q1**：本课示意预算下，SWC RAM 从 45 KB 涨到 60 KB，总占用多少？该不该换更大 MCU？
**Q2**：为什么"换 MCU 只换 MCAL"对电池厂是卖点？
**Q3**：裸机路线要自证的安全机制至少列四项。

<details><summary>答案</summary>

- Q1：86 − 45 + 60 = 101 KB → **79%**，超 67% 警戒且几乎吃光余量；应换更大 RAM 档位或砍 BSW 配置。
- Q2：算法 SWC 不动就能迁移到新芯片平台——电池厂的核心资产（算法）获得平台无关性，谈判时换芯不受制于人。
- Q3：程序流监控（看门狗/问答式）、E2E 保护（计数器+CRC）、RAM/Flash 完整性（ECC/测试）、存储保护（MPU 分区）、中断与栈溢出防护（任答四项即可）。
</details>
