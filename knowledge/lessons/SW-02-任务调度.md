# 课程 SW-02：OS 与任务调度——分层周期与 WCET 验证

> 对应节点 `SW-02`（[../domains/04-软件设计.md](../domains/04-软件设计.md)）｜ 前置：[SW-01](SW-01-软件架构.md) ｜ 预计用时 60 min
> 数字规则：文中具体数字凡未挂标准/来源者均为**教学示意值**；调度理论的结论（RM 上界、RTA）为经典实时系统理论。

## 1. 为什么调度是"隐形的保护功能"

节点约束点题：**典型采样 10~100 ms / 算法 10 ms~1 s 分层；需 WCET（Worst-Case Execution Time，最坏执行时间）验证**。调度错的症状不是崩溃，而是**慢**：采样任务被饿死 → 数据断档 → SOC 跳变；保护环超期 → 过流响应晚一拍。调度设计就是把"每件事都在截止期前做完"变成**可证明**的结论，而不是"测试时没出问题"。

## 2. 机制展开：OSEK/AUTOSAR OS 的调度模型

**（1）固定优先级抢占调度**：每个任务静态分配优先级，高优先级随时打断低优先级。中断高于一切任务；任务内只做"取数、算、置标志"，重活推迟到任务级（防中断里做算法）。

**（2）任务分层表（教学示意值）**

| 任务 | 功能 | 周期 T | WCET C | 截止期 D |
|---|---|---|---|---|
| τ1 | AFE 数据搬运与校验 | 1 ms | 0.15 ms | 1 ms |
| τ2 | 保护/控制环 | 10 ms | 1.5 ms | 10 ms |
| τ3 | SOC/SOP 算法 | 100 ms | 8 ms | 100 ms |
| τ4 | 诊断、记录、通信管理 | 1000 ms | 20 ms | 1000 ms |

分层节奏与节点约束（采样 10~100 ms / 算法 10 ms~1 s 分层）对应；周期越短优先级越高（速率单调 RM 排序法）。

**（3）Alarm/计数器驱动**：硬件定时器计数器驱动 Alarm，按表激活任务——周期由硬件保证，不靠软件延时（软件 delay 不可证明）。

**（4）基础任务 vs 扩展任务**：基础任务一口气跑完（可证明性好）；扩展任务可阻塞等待事件（表达力强但分析变难）。安全关键路径倾向基础任务。

## 3. 手算实例：可调度性两层验证

**第一层 — 利用率上界（快速筛查）**：U = ΣC/T = 0.15 + 0.15 + 0.08 + 0.02 = **0.40**
RM 充分条件：U ≤ n(2^(1/n) − 1)，n = 4：U_max = 4 × (2^0.25 − 1) ≈ **0.757**。0.40 < 0.757 → 初筛通过 ✓（适用前提：D = T、任务独立、全抢占、固定优先级）。

**第二层 — 响应时间分析（RTA，正式验证）**：任务 i 的最坏响应 R_i = C_i + Σ⌈R_i/T_h⌉ × C_h（h 为更高优先级任务），迭代到不动点。以 τ4（最低优先级）为例：

- 初值 R₀ = C₄ = 20 ms
- R₁ = 20 + ⌈20/1⌉×0.15 + ⌈20/10⌉×1.5 + ⌈20/100⌉×8 = 20 + 3.0 + 3.0 + 8 = **34 ms**
- R₂ = 20 + ⌈34/1⌉×0.15 + ⌈34/10⌉×1.5 + ⌈34/100⌉×8 = 20 + 5.1 + 6.0 + 8 = **39.1 ms**
- R₃ = 20 + ⌈39.1⌉×0.15 + ⌈39.1/10⌉×1.5 + 8 = 20 + 6.0 + 6.0 + 8 = **40 ms**
- R₄ = 20 + 6.0 + 6.0 + 8 = **40 ms** → 不动点，R₄ = 40 ms ≤ D₄ = 1000 ms ✓（余量 25 倍）

同理可验 τ3（R₃ = 12.95 ms ≤ 100 ms ✓）。**结论：本任务集可调度**——注意 U = 0.40 但最低优先级任务的最坏响应已放大到 WCET 的 2 倍，这就是只用"利用率感觉"判断的风险。

## 4. 工程实态

- WCET 三种来源：静态分析（工具）、测量（示波器/GPIO 翻转 + 全边界激励）、厂商基准——正式证据要求覆盖所有分支（含故障分支），ISO 26262-6 要求 WCET 与栈深有分析证据（S-07）；
- 栈深分析同法：每任务栈 + 中断嵌套最深栈求和，配栈溢出检测（MPU 水位线）；
- 抖动管理：采样任务被抢占导致采集时刻抖动，影响滤波与差分计算——高精度同步场景用 ScheduleTable 或提高采样任务优先级；
- 故障降级态要重跑调度分析：故障时记录/诊断任务变多，往往才是最坏时刻。

## 5. 常见误区

1. 用 U < 1 判断"可调度"——利用率 90% 的任务集照样有任务错过截止期，正式结论必须 RTA；
2. 裸机大循环"顺序执行万事大吉"——轮询无截止期保证，慢一环全线后移；
3. 中断服务程序里做算法/发报文——高优先级中断被拉长，整表响应崩坏；
4. 优先级按"直觉重要性"定——应按周期/截止期（RM/DM 法）定，直觉排序会造出不可调度集。

## 6. 自测

**Q1**：τ2 的 WCET 涨到 2.5 ms 后，U 变多少？初筛还过吗？
**Q2**：为什么采样任务（τ1）周期最短就要给最高优先级？
**Q3**：RTA 里 ⌈R/T⌉ 的含义是什么？

<details><summary>答案</summary>

- Q1：U = 0.15 + 0.25 + 0.08 + 0.02 = **0.50**，仍 < 0.757 初筛通过；但需重跑 RTA 才能给正式结论。
- Q2：RM 理论最优性：周期短（截止期紧）的任务优先级高时任务集可调度性最好；且采样是所有下游的输入源，晚一拍污染全体。
- Q3：在响应窗口 R 内，更高优先级任务 h 会抢占 ⌈R/T_h⌉ 次，每次干扰 C_h——即"窗口内最坏被插队次数"。
</details>
