# Skill: 资料入库与内容蒸馏

## 核心规程

**"读完再写"是硬规则。** 对于视频类链接，不允许仅根据标题、简介或字幕摘要生成笔记；必须基于可获得的最完整内容（字幕全文 / 文字稿 / 章节信息）进行蒸馏，并在笔记头部声明"本笔记基于何种内容载体生成（字幕全文 / 人工转写 / 官方文字稿）"。

## 资料分级

按可信度分为三级，入库时必须标注：

- **A 级（规范性）**：标准、法规、厂商官方技术文档、经过同行评议的期刊/会议论文。
- **B 级（解释性）**：权威技术媒体、头部研究机构报告、厂商技术博客。
- **C 级（线索性）**：个人博客、论坛、自媒体。C 级只能作为"待验证线索"入库，不能直接进入知识图谱的事实层。

## 视频处理流程

1. 获取字幕/文字稿全文。若无法获取全文，标记 `[内容不完整，仅作线索]`，不产出"有用内容"。
2. 按以下结构蒸馏：
   - 视频的核心问题是什么（1 句）
   - 讲者给出的关键判断 / 数据 / 方法（分条，每条附时间戳或段落定位）
   - 与已有知识图谱节点的关联（引用 node id）
   - 讲者立场或利益关联声明（如厂商演讲，注明）
3. 写入 `sources/videos/`，文件名格式：`YYYY-MM-DD_讲者_主题.md`。

## 非视频资料处理

- 论文：提取"问题—方法—证据—局限—对BMS工程的含义"五元组，写入 `sources/papers/`。
- 标准：提取适用范围、关键条款、与其他标准的引用关系，写入 `sources/standards/`。
- 厂商文档：标注厂商名称、产品/平台名、文档版本或发布日期，写入 `sources/official/`。

## 输出约束

每条蒸馏笔记末尾必须有一行：

```
INTAKE_CONFIDENCE: A/B/C | SOURCE_TYPE: paper/standard/video/official/blog | FULL_CONTENT_READ: yes/no
```
