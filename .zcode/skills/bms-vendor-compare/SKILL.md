# Skill: 厂商 BMS 对比矩阵

## 第一层：角色差异（必须最先区分）

BMS 的"强弱"只有在角色边界内才有意义。

**电池厂 BMS**：核心职责是"把电池管明白"——单体/模组/Pack 内部的温度点、均衡策略、SOC 跳变、硬件实现、算法开发、验证交付。技术追求是深度、标准化、平台化、通用可靠性。

**主机厂 BMS**：核心职责是"把车管明白"——整车热管理联动、充电策略与不同桩的匹配、OTA 对 SOC 算法的远程修改、售后故障码的归属判断、与 VCU/热管理/充电/OTA 团队的协同。技术追求是系统集成、整车匹配、用户体验和问题闭环。

**输出要求**：任何厂商对比必须先声明被比较对象属于哪一类角色。不能拿电池厂的算法深度去否定主机厂的系统集成能力，反之亦然。

## 第二层：厂商间差异的实证维度

不要停留在"技术路线不同"的笼统表述。以下维度必须有具体证据才写入矩阵：

1. **SOH 定义与上报语义**：同一 UDS $22 服务下的 F190/F191/F1A0 等 DID，不同供应商在单位（% vs Ah vs kW）、精度、刷新机制（事件触发 vs 周期上报）上存在实质分歧，背后绑定的是电化学模型假设和老化路径建模粒度的差异。
2. **架构选择**：集中式 / 分布式 / 主从式 / 无线 BMS；CTP/刀片等无模组化结构如何改变 BMS 的物理边界和热管理耦合方式。
3. **算法侧重**：例如宁德时代被提及的"多尺度参量耦合算法"在充电末端（SOC>80%）的速率保持能力（待交叉验证）；LG Energy Solution 的 BMS 相关后市场服务矩阵（B-Lifecare / B.once / B.around / KooRoo）反映的是"数据服务化"路线。
4. **商业模式与数据主权**：电池厂倾向于把 BMS 数据能力打包为后市场服务；主机厂则倾向于掌握整车匹配、故障策略和 OTA 权限，避免电池成为"黑盒子"。
5. **功能安全与验证策略**：ASIL 等级分解、AI 验证方式、云端-边缘协同的实时性约束。
